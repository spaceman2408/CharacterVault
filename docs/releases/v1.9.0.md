# CharacterVault 1.9.0

CharacterVault 1.9.0 lets you save an endpoint and model as a named preset and switch between them from the AI Config dropdown, adds Moonshot (Kimi), Z.ai (GLM), Z.ai Coding Plan, and DeepSeek presets, and makes the library quicker to search and sort with clickable tag chips, search shortcuts, and a Created sort, plus bigger Agent batches and fixes for thinking and reasoning models.

**Try it:** https://vault.charactervault.app
**Staging:** https://staging.charactervault.app
**Docs:** https://vault.charactervault.app/docs/

---

## Highlights

### Saved presets

Keep the endpoint and model pairs you use under names of your own. In **Settings → AI Config**, pick a provider or **Custom URL**, pick a model, then click **Save as preset** under the URL field. The name starts as the provider and model, like `OpenRouter · kimi-k3`; press **Enter** or **Save preset**. The preset shows under **Saved** in the **API Base URL** dropdown, and picking it switches to that endpoint and model.

- **One key per endpoint**: presets on the same endpoint share its saved key, so one OpenRouter key covers Kimi, GLM, and DeepSeek presets side by side.
- **Built-ins stay put**: plain OpenRouter (or any built-in) keeps its own model when you switch to a saved preset and back. Change the model while a saved preset is selected and the dropdown goes back to the plain provider, ready to **Save as preset** again.
- **Custom endpoints by name**: the endpoint list under **Settings → Prompts → Model for this prompt** shows saved custom endpoints by their preset name.
- **Removing and clearing**: **Remove preset** asks first and leaves the URL, key, and model in place. Saving and removing take effect on **Save Settings**. **Clear AI Settings** keeps your presets but drops their keys, and settings backups include them.

[AI Setup → Saved presets](/configuration/ai-setup#saved-presets)

### New provider presets

**Settings → AI Config → API Base URL** adds four direct endpoints, each with a **Get your key** link. All four fetch their model list from the browser.

- **Moonshot (Kimi)**: Kimi models, pay as you go. Kimi's coding-plan endpoint blocks browser requests, so it is not offered.
- **Z.ai (GLM)**: GLM models, pay as you go.
- **Z.ai Coding Plan**: GLM models on a GLM Coding Plan subscription, with a normal Z.ai key.
- **DeepSeek**: DeepSeek models direct from DeepSeek.

[AI Setup → API Base URL](/configuration/ai-setup#api-base-url)

### Library search and sort

Finding a card in a big library takes fewer clicks.

- **Tag chips**: click a tag on a library card to fill the search with it and narrow the grid to cards with that tag. The **+N** chip still opens the card details.
- **Search shortcuts**: a **×** clears the search once you type. **Escape** clears it, and **Escape** again leaves the box. Press **/** anywhere on the library (not while typing) to jump to the search.
- **Created sort**: next to **Name** and **Recent**, **Created** puts the newest created or imported cards first. Your choice is remembered like the other sorts.

[Vault Organization → Search](/features/vault-organization#search)

### Also in this release

- **Bigger Agent batches**: one Agent reply can hold up to 24 tool calls (was 12), and a run can make up to 150 lorebook entry updates (was 50), so large lorebook passes stop hitting **max updates per run**.

## Fixes

- **DeepSeek and Kimi thinking models**: Agent runs get past their first tool call instead of failing with an error about `reasoning_content`, also with **Remember earlier edits in the chat** on.
- **OpenAI reasoning models**: o-series and GPT-5 on api.openai.com keep your **Max Tokens** limit in Orion and the Agent instead of failing or ignoring it.
- **OpenRouter**: a model that errors partway through a reply shows the provider's error instead of a cut-off reply shown as finished.
- **Agent spinner**: while the model writes its next reply, the spinner says **Working…** instead of staying on the last tool it ran.

## Upgrade

Client-only app. Open the hosted site, rebuild locally, or rebuild the Docker image; no server migration.

```bash
git clone https://github.com/spaceman2408/CharacterVault
cd CharacterVault
npm install
npm run dev
```

Running it with Docker? Pull and rebuild the image:

```bash
git pull
docker compose up -d --build
```

Local data from 1.8.5 keeps working. Saved presets are stored with your AI settings, and the library picks up each card's created date on first load for the Created sort. Hard refresh if the UI looks stale after deploy.
